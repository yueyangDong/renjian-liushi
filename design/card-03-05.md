## 一、为什么要这张卡

§7 情关注释写着三轴：「情（她对你，每年 −2，不维护就淡）／义（你欠她）／时（窗口，过期作废）」。
摸排结果：

| 轴 | 字段 | 状态 |
|---|---|---|
| 情 | `V.qing` | **在跑**：每折 −8，情关判定 `q = qing + (yun−50)×0.25` |
| 时 | `V.shi` | **在跑**：窗口计数，到期 `due`，永不复开 |
| 义 | `V.yi` | **空转**：`startLove` 初始化为 0，此后从未读写 |

另外 `V.mine`（你对她）也是半截：`startLove` 设了值、"追"时 +12，**从未被任何判定读取**。

结论：三轴只有两轴。义不是"没调好"，是整条没有。本卡补上，并顺手把 `mine` 的去留裁定。

## 二、义是什么（判定）

**义 = 你欠她的。不出数，只给一句话。** 与情相反：

- 情会淡（每年 −8），**义不会淡** —— 债不因时间消失；
- 情是她的心，义是你的事；情决定能不能成，义决定成不成之后那笔账怎么落地。

### 2.1 来源（只认"她为你付出的年数"与"你从她那拿走的东西"）

| 来源 | 加义 | 说明 |
|---|---|---|
| 情关开着且为 B 型（她爱你，你不爱） | 每折 +3 | 她等你的每一年都是欠账 |
| A · 半（她应了，只是不像你待她那样） | +20 | 娶的是将就 |
| B · 娶 | +16 | 用一辈子还，但账并不因此勾销 |
| B · 不娶 | +20 | 欠的是她那些年 |
| B · 拖 | +30 | 拖到她自己把事了了，最重的一笔 |
| C · 挽回 | +18 | 钱买回了人，买不回那件事 |
| D · 扛 | +22 | 你替她家扛的债，她家从没认过 |

A 成、A 败、C 放手/被弃、D 放/私奔：**0**。你没欠她什么，那些是自己的念、疑、债。

数值口径说明：义账事件的门槛是 **16**，上表每条收场都单独越得过门槛
（否则会有三种"身子"是永远不触发的死代码——第一版设计按 B 型单线写，
A/C/D 的三条身子全部到不了 20，已修正）。B 型开着时的每折 +3 是厚度，
不是门槛。

上限 60（软顶）。义不衰减。

### 2.2 `mine` 的裁定

`V.mine`（你对她）删除，不落码。理由：三轴设定里没有第四轴；
"你有多爱她"已经由 情关四型（A/B/C/D）与选项文本承担，再开一轴是重复计量。
字段留着只会再长出一个"设了没人读"的半截。

### 2.3 阈值与可见性

- 义 ≥ 16：**义账**事件（一世一次，34 岁后、情关已了、非僧、未倒台）；
- 义 ≥ 16 未还：结局手记一句「临走前想起一个人，有一笔账没还上」——不扣数，只落字；
- 面板只给一句话，不给数：
  - 16 ≤ 义 < 40：`义 · 欠着一笔，没算清`
  - 义 ≥ 40：`义 · 这笔账压了半辈子，快压不住了`
  - 义 < 16：不显示（小账不值得说）

## 三、义账事件（一世一次）

事件 id `yidebt`，按情关怎么收场分四种身子、各三选：

| 身子 | 触发收场 | 三选 |
|---|---|---|
| 她病了 | B · 娶 | 回去（财−6 寿−4 誉+6，义清）／托人（财−8 誉+2，义−12）／不回去（誉−6，义不还） |
| 她托人带话 | B · 不娶/拖 | 说实话（寿−2 誉+4，义清）／拖几天再回（寿−1 誉+2，义−12）／不回（誉−6，义不还） |
| 她娘家来求 | A · 半 / C · 挽回 | 借（财−12 誉+6，义清）／借一半（财−6 誉+2，义−12）／不借（誉−8，义不还） |
| 她家不认账 | D · 扛 | 认了（寿−4 誉+6，义清）／要个说法（财−4 誉+2，义−12）／算了（誉−6，义不还） |

设计意图：**义账不是道德审判**。三个选项都有真代价——
全还最贵（钱、寿、位子），半还省钱但账留着，不还保住当下、拿誉去换。
游戏不告诉玩家哪个对，只告诉他要付什么。

选「不还」记 knot `欠`（命书里那句"记着"多一个字）。

## 六、实现记录

**落码（index.html）**
- `startLife`：`yi: 0`
- `stepLove`：B 型开着 +3/折
- `resolveKnot`：收场加义；`V.mine` 删除（含 choose 里的 +12 联动）
- `yiDebtEvent`：四种身子 × 三选；返回前 `L.used.push('yidebt')`
- `pickEvent`：knot 之后立刻判，防被后加的动态事件挤死
- `choose`：`o.yiPay`（99 全清 / 12 还一半）／`o.yiNo`（记 knot `欠`）
- `renderLife` 面板一句话；`endLife` 未还手记一句

**落码时抓到的两个问题（都不是笔误，是设计漏洞）**
1. **一世触发两次**：第一版没在 `yiDebtEvent` 里标 `used`，选"不还"之后义仍 ≥16，
   下一折又触发一次，把上一折的记录也覆盖了。游戏里其他动态事件
   （adopt/child/late/dark_*）都是自己在返回前 push，义账漏了这一步。
   回归台之所以先看到"不还 0%"，正是因为第二次触发把 `none` 覆盖成了 `full/part`。
2. **阈值让三种身子成死代码**：第一版按 B 单线定 20 门槛，A·半(10)/C·挽回(8)/D·扛(16)
   全部越不过，四种身子里三种永不出现。改为门槛 16、五条收场各自抬到 16~30。

**实测（300 局 × 6 策略，基线 v5）**
| 策略 | 义账触发 | 全还 | 半还 | 不还 |
|---|---:|---:|---:|---:|
| 随机 | 18.3% | 8.7% | 9.7% | 6.7% |
| 专精 | 43.7% | 43.7% | 0 | 0 |
| 顾家 | 36.3% | 36.3% | 0 | 0 |
| 贪心平衡 | 14.7% | 2.7% | 0.3% | 11.7% |
| 孤臣 | 0 | — | — | — |
| 走黑路 | 0 | — | — | — |

- 随机均匀（三选各约 1/3），说明选项没有隐藏过滤；
- 专精/顾家的选项没有 `cai`／`室子` 键，并列取先 → 全选全还。这是**并列取先**，
  不是数值定死：这两条策略本来就不看情义，抽到义账就等于替玩家默认还款。
  贪心平衡（看六事边际）明显偏不还（11.7% vs 2.7%）——同一个事件在不同打法下
  出现相反的选择，正是想要的"真代价"。
- 孤臣/走黑路为 0：孤臣不议亲（无 love → 无义），走黑路多死在 34 岁前。
  这两个 0 是结构性的，不是漏码。
- 全量回归：六策略 59 项全 PASS（基线 v5），0 FAIL。
