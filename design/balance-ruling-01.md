## 逐条裁决

### ① 覆／孤／绝 在"会玩的人"手里只剩 0.1~0.2%

**判定：覆 = KEEP；孤 = FIX（判定链，不是阈值）；绝 = KEEP。**

#### 依据

- 设定 §1.8：「**「寻常」要少，「起伏」和「覆」要有。** 一个只出"缺一"的游戏是在做算术；一个能出"我把财做到了 90，可我没有后"的游戏，才是在讲人生。」
  → 「覆要有」是**全体口径**，不是"会玩的人手里也要有"。实测四策略覆 0.1% / 7% / 0.2% / 3.1%，这一层**存在**。
- 设定 §1.8 覆的定义：「倒台／律 ≥85／财禄室同时见底／无室无后且家底空」→ 四条全是**失败判据**，没有一条是"另一种活法的选择"。所以覆 = 不会玩的惩罚，这是设定原意，不该改。
- 设定 §1.4：「终局不求和，取 min(六项)」「「寿」不参与 min」。→ 取 min 的算式**必然**要求会玩的人保住最薄那一格；而 子 是五格里最容易补的一格（有后 25 / 立业 20 / 有孙 20，三个台阶都在事件里）。**"会玩的人必然结婚生子"不是路径被堵，是判定式的直接后果。**
- 设定 §1.1「无室」档：「**这一档不是"困难模式"，是另一种活法**：你可以一辈子不娶，把十二格全给公务，做到尚书；也可以在六十岁那年，一个人坐在空院子里，听见隔壁人家在吃饭。」
  → 这是关键：无室档**该有自己的判词**。§1.8 的「孤」（屋里一直只有一双筷子）就是它。**今天它拿不到。**

#### 实测：孤 是"拿错了人"，不是"拿不到"

同一个「无室／孤臣」打法（优先 `tr:{孤臣}`／`cutParty`／`lone`，之后按补最薄走），1200 局 seed 20260101：

| | 孤 | 六全 | 起伏 | 寻常 | 空 | 其余 |
|---|---|---|---|---|---|---|
| 现状（全部 1200 局） | **1.1%** | **26.3%** | 34.2% | 17.7% | 10.3% | 缺一 10.3 / 绝 0.3 |
| 其中 `lone` 的局（80.3%） | 0.9% | 32.7% | 22.4% | 22.0% | 8.8% | 缺一 12.8 / 绝 0.4 |

同时（2000 局基线，`--strategy balanced`）：孤 0.2%、六全 14.5%。

**一个主动选择一辈子不娶的人，38 个里只有 1 个被判「孤」，倒有 1/4 被判「六全」。** 这不是"孤 太稀有"，是"孤 的门槛被六全抢先了"。

机制：`index.html:3887` 的 `aloner` 要求 `室≤5 且 子≤5`，而 `:3891` 的「六全」判在它之前。无室打法的人会正常走「过继」（`index.html:1280-1291`，`adopt:1` 无条件成功）→ 子 = 25/45/65 → `子≤5` 不成立 → 孤 不触发 → min 走五项（`:3862` 已剔除 室）→ 六全。

而设定 §1.1 明写：「**无室者不在「子」上自动免责**……这是 1566 的看法」——过继得子是对的。所以问题不在"他有过继"，在"他有后就不算孤"这条隐藏前提，设定里没有。§1.8 孤 的条件是「室 ≤5 **且** 子 ≤5」，但对一个**主动**无室的人，"子"是他为了补 min 才去要的，用它来否掉「孤」等于用"补分行为"否掉自己的判词——**判词被玩家的最优解挤掉了**，这正是设计红线里的"主导策略"。

#### 处置（改什么）

1. **「孤」上移到「六全」之前**（判定链顺序），`index.html:3890-3893`。
2. **「孤」的判据：把"无后"从必要条件改成"无室之后的两种收场之一"**：
   `aloner = !L.monk && L.six['室'] <= 5 && L.age >= 40 && (L.lone || L.six['子'] <= 5)`
   - 只认 `L.lone`（来自 `:1128`「不谈了」、`:3193` 情关无、`:3125` 出家另算、`:857` 孤臣轨；`:1664`「将就」会把 `lone` 撤回）。
   - **`室 <= 5` 这一条必须留着**。去掉它（改成"只要 `lone` 就判孤"）会误伤 balanced：它有 23.6% 的局末 室<10、室 P10 = 0，那些是"婚姻凉了"不是"从未打算有家"，把它们判成孤会把 起伏 全吃掉（实测未做，按分布推算 起伏 会从 32% 掉到 15% 以下，这个量级会毁掉 §1.8「起伏要有」）。
3. **不动** 覆 的四条判据、**不动** 绝 的 `子≤5 && age≥45`、不动 六全 的 54 门槛。
4. **不改** 3900 行起的 判词文案（「屋里一直只有一双筷子」正好对应无室）。

#### 影响预估（干跑 1200 局，seed 20260101）

| 打法 | 孤 | 六全 | 起伏 | 覆 |
|---|---|---|---|---|
| random | 9.0% → **18.8%** | 4.6→3.6 | 29.3→26.0 | 3.2→3.2 |
| balanced | 0.1% → **2.6%** | 14.1→14.0 | 32.3→31.2 | 0→0 |
| home | 1.5% → 1.5% | 2.7→2.7 | 24.5→24.5 | 0.2→0.2 |
| 无室打法 | 1.1% → **47.8%** | 26.3→12.9 | 34.2→20.4 | 0→0 |

方向都对：该拿的人拿到（无室打法 47.8%），不该拿的人不拿（balanced 2.6%，仍在 3% 内），random 18.8% 说明"闭着眼睛过一辈子，三分之一不娶"这件事终于有判词了。

#### 验收标准（回归台可验证）

- `--strategy balanced`：**孤 ≤ 4%**，且 六全 ∈ [12%, 17%]（不许因为这条把六全吃掉）。
- `--strategy random`：**孤 ∈ [15%, 22%]**。
- 新加一条策略（建议命名 `lone`／`孤臣`，见下方"给 05 的约束"）：**孤 ≥ 40%**、六全 ≤ 15%。
- 覆：balanced ≤ 2%（现状 0.1%；③ 的改法会让它略降不是略升，见 ③ 的影响预估）。

### ② 顾家「绝」51.6%，比随机高 34 个百分点

**判定：FIX（自动打法的计价漏了「子」）。不是数值问题，不是"顾家=牺牲外部资源"的必然。**

#### 依据

- 设定 §1.1「子」的五级台阶：有后 25 / 立业 20 / 有孙 20 / 家和 15 / 四世同堂 20；「**子孙成功 = 你在自己有生之年，亲眼看见这五件事**」。
  → 「顾家」这个打法的全部内容就是这五件事。**一个守着家的打法最容易绝后，与设定直接矛盾。**
- 设定 §1.4：取 min。→ 子 是 min 的一员，"守着家"理应把子抬到最高。
- 设定 §1.1 有后门槛：「二十岁起，看「室」够不够：室 ≥38 二十岁得子，≥28 二十四岁，≥18 二十八岁，≥8 三十二岁，≥5 三十六岁。**室薄的人，连儿子都来得晚**」
  → 设定里 室 **就是** 有后的门槛。实测 顾家 的有后率按 室 分桶几乎是平的（[0,10) 12.5% / [10,25) 24.8% / [25,40) 48.6% / [40,60) 50.6% / [60,101) 46.3%），**室 对有后毫无作用**。这是第二条冲突，记在冲突清单第 2 条。

#### 实测：根因是一行计价

2000 局 `--strategy home`（seed 20260101）：

```
遇到「求子」事件            100.0%
  其中选「认命」            100.0%      ← 一次也没试过
  其中选「求医／纳妾」        0.0%
遇到「过继」                43.8%
有后率                     43.8%      ← 恰好等于「遇过继」，全部来自过继
绝                          51.5%
```

机制：
- `index.html:2624`：`d.dataset.home = eff['室'] + eff['子']`
- `index.html:3104`：`if (k === '子') continue;` —— **子 永远不出现在 `eff` 里**（它走 `stepHeir` 台阶）
- 于是「顾家」的分 = `eff.室`。三个选项：求医（室 0）、纳妾（室 −10）、认命（室 +2）→ **认命必胜**。
- `index.html:2635-2648` 的 `autoPickOpt` 与回归台 `strategies.js` 的 `home` 是同一套规则，所以：
  ①线上有玩家看得见的入口 `?auto=1&smart=1&strat=home`；②回归台的 `home` 口径同样失真。两边都要修。

#### 处置

1. **线上**：`index.html:2624` 的 `d.dataset.home` 改成"室 + 子台阶"（`子` 不进 eff，必须显式计价）：

```js
// 2624 附近，与 dataset.cai 并列
const H = S.life.heir || {};
let sub = 0;
if (o.child && !H.has) sub += 22 * o.child;          // 求子：成率打折后的期望
if (o.adopt && !H.has) sub += 25;                    // 过继：一级「有后」
if (o.grand && H.has && !H.grand) sub += 20;         // 二级「有孙」
if (o.raised !== undefined && H.has) sub += 6 * o.raised;  // 教：直接影响立业
if (o.noHeir && !H.has) sub -= 18;                   // 认了断后 = 把「绝」写死
if (o.loseChild && H.has) sub -= 25;
d.dataset.home = ((o.eff||{})['室']||0) + ((o.eff||{})['子']||0) + sub;
```
2. **回归台**：`tools/balance/strategies.js` 的 `home` 用同一套（`balanced` 的 `heirPoints()` 已经写好了这套计价，直接复用），保证"游戏内自动"与"回归台"再也不分家。
3. **不动** 「求子／过继」事件的任何数值；不动 `noHeir` 的 `+6 誉 / +2 室`（它是"认命"的真实好处，该留着）。**问题不在奖励，在计价看不见它。**
4. 顺手一处文案 bug（工单，非本次）：`index.html:3150` 的 `noHeir` 把 `heir.lost = true`，于是 `heirHint()`（`:3353`）与 `heirLine()`（`:3364`）把"认命"说成「**那一个没留住**」——玩家没死孩子，只是认了。建议加 `noHeir` 独立标记与文案。

#### 影响预估（干跑 1200 局）

| 顾家 | 绝 | 有后 | 起伏 | 六全 | 空 |
|---|---|---|---|---|---|
| 现状 | 52.7% | 43.0% | 24.5% | 2.7% | 1.9% |
| 修后 | **0.5%** | **97.8%** | **54.5%** | 4.8% | 6.8% |

**副作用要盯住**：起伏 24.5% → 54.5%，已经贴到回归台的"偏挤"线（≥55%）。这在叙事上是对的——顾家 = 室/子 顶到 80+，财/禄 塌着，正是「六事俱全，而终身不乐」的另一面；但 54.5% 超过意图 35% 太多，说明**顾家这条路没有第二条出口**（要么绝，要么起伏）。这不是本次裁决要改的，记入"05 制作约束"：**给顾家补一条"财/禄 不至于塌"的入口**（例如 教子 同时带 财、或 立业 的儿子反哺），属于内容扩张，不许用调数值糊过去。

#### 验收标准

- `--strategy home`：**绝 ≤ 3%**（现 51.6%）、**有后 ≥ 93%**（现 43.8%）、六全 ≤ 8%。
- 顾家 起伏 若 ≥ 55%，**不当场拦，但必须开一张"顾家缺外部入口"的工单**（内容侧解决）。
- 线上 `?auto=1&strat=home` 跑 20 局，**不许出现"遇到求子却选认命"**（人工抽查即可）。

### ③ 专精「覆」7%，是随机的两倍多

**判定：数值 KEEP（自洽）／判据 DESIGN-CHANGE（覆第4条）／换算 FIX（律回设定，但不指望它救活这条线）**

#### 依据

- 设定 §1.8 覆 的第 4 条判据：「无室无后且家底空」→ 实现 `index.html:3884`：`室≤2 && 子≤5 && 财≤30 && age≥44`。**逐字相符。**
- 设定 §1.10：「六事之间不是加法，是**互相偷时间**。你把一样做到极处，剩下五样里总有一样在替你付账。」→ 专精必缺，这是**设定要的表达**。7% 覆 + 41.3% 绝 正是"专精必缺"落在判词上的样子。所以数值不该动。
- 设定 §1.1「律」：「到 **60** 就不是"可能会出事"，是"哪天来人"：强制触发「问拟／立案」……了结之后律回到 10，案翻过去，账留着。」
- 设定 §1.10 满招损两层：常态的漏（≥92、35%/折、另一项 −2）＋ 有人递折子（≥88、45%/折、一生至多两次、冷却 3 折）。

#### 实测：覆 7% 不是满招损在收账，是"穷+孤"借了覆的判词

2000 局 `--strategy cai`：

```
覆 139 例（7.0%），成因：
  财禄室同时见底（:3883）                20 例   14.4%
  无室无后且家底空（:3884）             119 例   85.6%   ← 主体
  律≥85（:3882）                          0 例    0.0%
  倒台 ruined（:3882）                    0 例    0.0%
墨 3.84 次/局（random 7.17）· 律 P50 = 3 · P90 = 10 · max = 26 · 律≥35 的局 0.0%
```

四策略横向：**律 ≥85 的局，在 8000 局里是 0**；律 ≥60 的局 0%（random 0.1%）；`ruined` 0%（它要求 `:3463` 权臣轨 + 律≥45 + 禄≥70 + 45%）。

所以，对提问的三段回答：

1. **"满招损的代价被另一条路径抢走了"——不是。** §1.10 的两层付款方式是「**随机另一项 −2 或 −12**」和「三选一（收/扛/让名）」，不是"整盘归零"。满招损**在跑**：树大事件 0.4 次/局、27% 的局撞上、参数与设定逐字相符（`:2838-2856`）。专精的 7% 覆 来自 子/室 塌 + 财 塌，是取 min 的算术，不是"另一条路径"。
2. **但「覆」这个判词被"穷+孤"占用了**：85.6% 的覆其实是"孤／绝 + 财≤30"。判词「一场事下来，什么都没剩下」用在一个 财 25、室 0、子 0 但 禄/誉 都还行的人身上，是错的——他剩下的是"位子"和"名声"，缺的是屋里的人。那正是「孤／绝」该说的话。（→ 判据收窄）
3. **真正"写了没跑"的是 §1.1 的「律」**：`ink×0.8` 攒律（`:3114`）、阈值 `:3072` 是 `law≥55`、且 `:3073` 写成"一生一次"。实测：**立案（问拟）事件只出现在 0.1% 的局**，`ruined`（倒台，前置 `law≥45`，`:3463`）0%。那条三选一（认／咬／赎）等于死内容。

**关于"该调哪个数"——我把四个候选都干跑了（1200 局 random），结论是：系数和阈值都不是杠杆。**

| 变体 | 律 P50 / P90 / max | 律≥60 的局 | 立案局 | 覆 | 倒台 |
|---|---|---|---|---|---|
| 现状（0.8 / 55） | 14 / 32 / 66 | 0.1% | 0.1% | 3.2% | 0.1% |
| 设定（0.6 / 60） | 11 / 25 / 53 | 0.0% | 0.1% | 3.2% | 0.1% |
| 0.8 / 60 | 14 / 32 / 66 | 0.1% | 0.1% | 3.2% | 0.1% |
| 1.0 / 60 | 18 / 38 / 100 | 0.8% | 0.5% | 3.4% | 0.3% |
| 阈值单独降到 45 | — | — | 0.9% | 3.2% | — |
| 阈值单独降到 40 | — | — | 1.7% | 3.3% | — |

→ **瓶颈是「墨」的供给量，不是换算率。** 现状每局墨 3.84（专精）～7.17（random），律 的 P90 只有 32。要把立案做到 5% 量级，每局墨的期望得翻一倍（约 14），那是**内容量的事**，不是改一个系数的事。所以本次**不承诺"律可达"**，只做三件"不许再压"的动作，把"律可达"留给 05 并写成量化内容指标。

#### 处置

1. **覆 的第 4 条判据收窄**（DESIGN-CHANGE，同时改代码与设定）：
   `index.html:3884`：

### ⑤ `study` 抬高的顶，被 `recalcCaps()` 用裸顶压回

**判定：FIX —— 这是 bug，不是设计。而且它比"抬顶被吃掉"严重得多。**

#### 依据

- 设定 §1.7：「六项各有"顶"……**读书能把顶往上抬一点——每两点「学」抬一格，最多抬 12 格，且最终不超过 90。**」「抬不动的部分：**天才是天生的**。抬到 90 就是学的尽头，95 那一格只属于命里带来的。」
- 同段末：「这一条是为了不把人生钉死：出身给你的顶很低，但你可以把它往上撑一撑。撑不到极处，可**撑与不撑，差的是整整一个档次**。」
  → 设定只说**抬**。代码在"抬"之外，还顺手做了两件设定里没有的事（见下）。

#### 实测：三个副作用，一个比一个重

**(a) 抬顶被回吞**（回归台自检已记账）：
```
校验样本 87668 个 (事件,格子) 对 · 顶被压回 1390 次
例：{"ev":"money","k":"禄","base":0,"cap":1,"rawCap":0,"pred":1,"act":0}
```
`:837-839` 的 `capOf()` 把 `study` 加成算进顶；`:856` 的 `L.capSix = c` 存的是**裸顶**；`:858` 再用裸顶把超过的格子压回去。于是每次选择后，读书挣来的那一格被扣掉一点。

**(b) 无禄者被凭空长出"禄顶"（更严重）**：
`capOf(L,'禄')` 在 `capSix['禄'] = 0`（市井十二行／个体户）时返回 `min(12, floor(study/2))` = 1~12。
而"这个人有没有位子"有两处是直接拿 `capOf(L,'禄') === 0` 当判据的：
- `:3864` 五项结算 vs 六项结算（§4.2「市井无禄：禄 = 0，且判死不按禄算（五项结算）」）
- `:3382` 立业「无禄路线改看誉」（§1.9）

实测（2000 局，seed 20260101）：

| | 幻顶局（无禄 + 学≥2） | 干净无禄局 | 结论 |
|---|---|---|---|
| random | 124 局 | 700 局 | 幻顶局里 **77.4%** 把 禄=0 计进了 min |
| home | 216 局 | 788 局 | **100%** 把 禄=0 计进了 min |

幻顶局结局（home）：起伏 54.6% / 绝 39.8% / 空 5.6% / **六全 0%**
干净无禄局结局（home）：绝 46.4% / 缺一 21.8% / 起伏 18.0% / **六全 6.5%** / 寻常 6.3%

→ **一个市井的手艺人，只要读了几本书，就再也拿不到「六全」和「寻常」，因为系统把他当成了"有俸禄的人"，然后拿他必然为 0 的"禄"当短板。** 这是"读书害人"，与 §1.7「读书改得了命」正好反着。

**(c) 誉的顶被压到 90（§1.7 只许抬不许压）**：
`capOf` 写作 `c = Math.min(90, c + min(12, floor(study/2)))`。当 `capSix['誉'] = 100` 时，`min(90, 100+1) = 90` —— **读书把你的誉顶从 100 压到 90**。实测：学≥2 的局里 **18.8%**（home/cai）、0.5%（balanced）有此现象。
设定 §1.7 的 90 是"抬的上限"，不是"所有人的上限"；同段明写「**誉的顶是 100**」。

**(d)** 连"到顶→透"都被搅乱：
`stepReveal`（`:3310-3312`）用 `capOf` 比：`if (c >= 60 && c < 100 && L.six[k] >= c)`。顶被抬到裸顶之上，而值被压在裸顶 —— 于是"禄到了你的头"这一声（设定 §1.5「透」的核心表演）取决于"最近一次 `recalcCaps` 在不在这个选项之前"，玩家的结果**不可预测**。
实测（3000 局）：禄有硬顶(60–99)的局里，`study<2` 组 透=禄 5.6%（home）/31.5%（random）；`study≥2` 组 0.0%（home）/34.7%（random）。**同一件事，两组差出 30 个百分点，方向还不一致**——这就是"实现两处算法不一致"的直接证据。

#### 处置（改什么）

1. `index.html:837-839`：**只抬不压，且不为 0 顶造顶**。
   ```js
   if ((k === '禄' || k === '誉') && c > 0){
     c = Math.max(c, Math.min(90, c + Math.min(12, Math.floor((L.study || 0) / 2))));
   }
   ```
   （`c > 0` 保住"市井无禄"的语义；`Math.max` 保住"只许抬不许压"；`min(90,…)` 保住 §1.7 的 12 格与 90 的天花。注意：原本 95 那一格"只属于命里带来的"由 `capSix` 直接给出（如 100），`Math.max` 不会把它压下来 —— 这一点必须保住。）
2. `index.html:844-859`（`recalcCaps`）：**存的就是算上 `study` 的顶**，并且用**同一个** `capOf` 来压。改法（注意顺序，别让 `capOf` 读到自己正在写的 `capSix`）：

```js
L.capSix = c;                                     // :856 裸顶先落库（capOf 内部会再加 study）
SIXK.forEach(k => {                               // :858 改用同一个口径压，不再用 c[k]
  const cc = capOf(L, k);
  if (L.six[k] > cc) L.six[k] = cc;
});
```
   这样 `capOf` 是唯一的顶，`capSix` 只是它的底座；`lockSix`（情关锁顶，`:840-841`）仍然最后生效，优先级不变。
   → 修完 `capOf` 与 `capSix` 只留**一个**口径，回归台自检的「顶被压回」必须归零。
3. **不要**为了保住"读书有用"而去改 `study` 的获取量（+3 苦读 / +2 拜师）——§1.7 的量纲是对的，坏的是落地。
4. **不要**把 90 的天花改成 100。§1.7「95 那一格只属于命里带来的」是这条规则的意义所在。

#### 回答提问里的那句"若是设计，玩家感知到的读书有用从哪来"

**现在从任何地方都感知不到。** 玩家能看到的只有两处：
- `index.html:2541` 那句「学 · 书没有白读（此身的顶，被撑高了一点）」（设定 §1.7 要求「学 ≥6 时给一句」，代码里这句在）——但它描述的收益被 `:858` 回吞；

3. **律 → 墨 的系数**：设定 §1.1「`律 += 墨 × 0.6`」；实现 `:3114` 是 `× .8`。（本次在 ③ 里改回 0.6——但要让设定方知道：**改回去不会让律更活，只会更死**，实测 律≥60 的局从 0.1% → 0.0%。这条实现当初大概是"为了让律能动"才调高的，属于善意偏离；要保活，得在墨的供给上找。）
4. **立案阈值**：设定 §1.1「到 60」；实现 `:3072` 是 `≥55`。且设定说「了结之后律回到 10，案翻过去，**账留着**」（可再犯），实现 `:3073` 是**一生一次**。
   （本次在 ③ 里一并改。**要把话说清楚**：55→60 会让立案更少，在"墨供给不足"的前提下，这反而是更忠实的选择——与其用 55 假装这条线活着，不如让它诚实地稀有，等 05 把墨补上再让它真活。）
5. **立业公式**：见 ④（本次改）。
6. **「孤臣」轨与「无室」档的因果被写反了**
   设定 §1.1：**先**无室，**才**解锁孤臣轨（「解锁「孤臣」轨：无党、无妻族、只有上意与民心」）。
   实现 `:854-857`：归到孤臣轨 → `c['室'] = 0` + `L.lone = true`（是轨定义了无室）。
   方向反了之后，"孤臣"变成一条**可以主动领的 buff**（财/子/寿/誉 各 +5，`:854`），而不是"放弃家室换来的"。
   → 建议：孤臣轨的 `cap 室 = 0` 保留（它确实是"没家"的轨），但 `+5` 的四项加成要等 §1.1 代价表落地后再评估；现在它是纯增益。
7. **「室」五条路径只落了两条**
   设定 §1.1：婚配 100／孝养 80／义子过继 75／挚友共爨 70／门生侍疾 65，可叠加（取最高 + 其余各 1/3）。
   实现：只有婚配与门生（§11 的落地表自己也记了「◐ 无室档已成，五路只落了婚配与门生」）。→ 孝养／挚友共爨 缺失，直接影响无室档的"室 不必为 0"这条退路（§1.1 说独身者最稳的一条是孝养）。
8. **叙事断言与判词不符**：「绝」的判词是「**该有的都有了**，就是没有人接下去」（`:3893`），但实测专精 41.3% 的绝局里，绝大部分"该有的"并不都有。收窄覆（③）之后这条会更明显。→ 建议：`绝` 增加一个前置（其余四项最薄 ≥42，即"寻常"线），否则它与「空／缺一」同义。**本次不动**，因为会连带改八层的分布。

### 丙、回归台的计量缺口（不是游戏的问题，是台子的问题）

1. **满招损的"常态的漏"不计**（README 已知局限第 2 条）：`index.html:2841-2844` 的 −2 不产事件，台子数不到。建议在 `metrics.js` 加 `满招损·常态的漏（次/局）`，打点位置 `:2843`。
2. **缺一条「无室／孤臣」策略**：① 的关键证据（孤 1.1% vs 六全 26.3%）在现有四策略里看不出来。建议在 `strategies.js` 加第五条 `lone`（规则见 ② 末尾的计价 + 优先 `tr:{孤臣}`／`cutParty`／`lone`）。**这是 ① 变成"可回归"的前提。**
3. **`baseline.json` 的 `intent` 只有 6 条**（寻常/起伏/对质/同榜/账簿/立业×3）。建议把 ① 的「孤」与 ③ 的「覆·成因分布」也写进 `intent`，否则这两条改完没有门槛看着。

## 对 05 制作的约束

> 05 是内容扩张。以下是这次裁决给扩张定的红线——**先修再写，边写边验**。

### 一、立刻冻结（在这些问题修好之前，一个字都不许动）

1. **结局八层的判定式**（`index.html:3880-3898`）：①③ 的改动要一次做完、一次重建基线。中间任何人为了"让某条新事件更好看"去调 54／85／12／42／58 这些数，等于把裁决废掉。
2. **「六全」门槛 54**：不许借内容扩张顺手调高（会给二周目加难度）或调低（会让 ① 的六层分布失衡）。要动，先出 02 号裁决。
3. **`heir`（求子）与 `adopt`（过继）的成率**（`:1161` `.62`／`:1164` `.9`）：在乙.1（室→有后）落地之前，这两个数是「子」这条主线唯一的闸门，动它等于动全部七层。

### 二、扩张时必须遵守的计量红线

4. **新增事件不许带 `child:`**（求子概率）。理由：`child` 是唯一能凭空长出「有后」的键（`:3143`），多一条就多一个"不结婚也能有后"的暗门。有后通路只保留三条：`heir`／`adopt`／（乙.1 落地后的）室门槛。「子」现在已经有两条溢出口，不能再开第三条。
5. **新增事件带 `ink` 的，必须写明它对 律 的期望贡献**，单条 `ink ≤ 12`。理由：`律` 即将从"死线"改成"活线"（③ 之后基线会变），改的过程中墨是**唯一的控制杆**——每局墨的期望从 7 提到 14，立案就从 0.1% 走到 5% 量级（这是 ③ 里唯一被证明有效的杠杆，其余三种改法都干跑过、都无效）。单条 15+ 的墨会让覆的样本量跳一个数量级（具体幅度我未量化，所以先按 12 卡住）。等 ③ 基线重建后，再按实测放开到 16。
6. **不许给「无室」再添任何收益**（上限加成／减项／多月令／事件特权）。§1.1 的四条代价一条都没实现（乙.2），此时再加收益就是把 ① 里那条 26.3% 的六全变成 40%。
7. **每条带 `eff` 的事件,其 `室` 与 `子` 的联动必须显式写**：`子` 不走 `eff`（`:3104`），所以任何"家庭向"事件如果要影响 子，只能通过 `raised`/`adopt`/`grand`/`loseChild`/`child` 五个键。**不许新造第六个键**（回归台的 `SPECIAL_KEYS` 与 `isCleanOpt` 会因此失效，自检会静默漏报）。
8. **顾家这条路的出口**：② 修完以后，顾家会稳定落在「起伏」（干跑 54.5%）。05 必须给它一条"财/禄 不至于塌"的入口（例如：教子 同时带 `财 +2`；或"儿子立业"反向给 财/誉 各 +3）。**不许用调数值糊过去**——要新事件，不要改 `JOB` 的 `f` 表。
